# Stages and gates

Each stage runs in its own session (`/stage N`, see `.claude/commands/stage.md`); the handoff between sessions is `docs/kb/progress.md`. Each stage: read the listed files, post a design note, stop on a real choice, implement with tests, post the summary, stop at the gate (protocol in `CLAUDE.md`). Budget: up to about 24 focused hours overall, submitted as early as possible. If time runs short, cut breadth, never the tests of core invariants.

## Definition of done (whole project)

- All invariants in `CLAUDE.md` hold and are covered by tests, including the stage 6 scenarios.
- `docker compose up` brings up Postgres, the app and the fake provider; a demo command places bets and the flow is visible in logs and metrics.
- Every assumption and business question has an ID, appears in `docs/PROVIDER_QUESTIONS.md`, and is referenced from the code where it matters.
- The README lets a reviewer understand the architecture, run it, and see what was deliberately left out, in under ten minutes.
